以前，我一直觉得个人网站放在 GitHub Pages 上就挺好的。

代码放在 GitHub，网站也直接由 GitHub 帮忙托管，整个过程简单、免费，而且对于一个个人博客来说，已经足够用了。

我的这个小站也是这样开始的。

没有复杂的后台，没有特别重的框架，文章、图片和一些页面内容都放在 GitHub 仓库里。想写文章的时候改一下 Markdown，提交到 GitHub，网站就跟着更新。

这种方式其实已经很好用了。

所以这次把网站搬到 Cloudflare，并不是因为 GitHub Pages 突然变得不好了。

只是折腾着折腾着，我发现自己现在对这个网站的要求，已经和最开始不太一样了。

---

我的网站叫「纳兰的个人小站」。

目前使用的仓库是 chennalan/nalan-website。

它并不是一个特别复杂的网站，本质上还是一个静态网站。

文章使用 Markdown 编写，然后通过自己的构建脚本生成最终的网站。

整个构建过程其实非常简单：

npm run build

然后生成一个 dist 目录。

这个 dist 里面，就是最终真正需要被浏览器访问的网页。

所以从技术上来说，我并不需要一个很复杂的服务器。

我需要的其实只是：

**一个能把 GitHub 里的代码构建出来，然后稳定地把静态文件放到网络上的地方。**

---

那为什么一开始选择 GitHub Pages？

因为它真的很方便。

尤其是个人网站这种项目，GitHub Pages 几乎不需要额外学习成本。

代码放 GitHub。

配置一下 Pages。

绑定自己的域名。

然后就结束了。

对于很多个人博客来说，这已经是一个非常舒服的方案。

而且 GitHub 本身就是我管理代码和文章的地方，所以网站和代码天然就在一起。

后来我甚至觉得，个人网站可能就应该这么简单。

直到我开始越来越频繁地折腾这个网站。

---

我开始给网站增加更多东西。

文章系统需要调整。

图片需要管理。

页面需要重新设计。

又开始研究文章阅读体验、目录、阅读进度、主题切换，还有照片墙。

网站慢慢从一个“能打开的个人主页”，变成了一个真正属于自己的小站。

这时候我发现一个很有意思的事情：

**以前我是在使用网站，现在我开始折腾网站本身了。**

而一旦开始折腾，就会希望自己能够掌控更多东西。

---

Cloudflare Pages 其实很适合这种情况。

我的网站本身是静态站，所以并不需要什么特别复杂的部署环境。

现在的部署方式是：

GitHub → Cloudflare Pages → 网站

代码依然放在 GitHub。

我依然通过 GitHub 管理文章和网站代码。

Cloudflare 只是负责把这些代码构建成网站，然后发布出去。

也就是说，我并没有放弃 GitHub。

恰恰相反。

**GitHub 还是我的代码仓库，只是网站不再由 GitHub Pages 托管。**

这两件事情其实完全可以分开。

---

迁移过程中，我还重新折腾了一遍自己的域名。

我的域名是：

chennalan.cn

以前它是绑定 GitHub Pages 的。

这次迁移到 Cloudflare，域名也需要重新处理。

这件事情看起来挺简单，但真正操作的时候，还是会遇到各种细节。

DNS 记录怎么改。

CNAME 指向哪里。

HTTPS 怎么生效。

自定义域名什么时候能正常访问。

有时候明明代码没有任何问题，网站就是打不开。

折腾半天以后才发现：

**原来只是 DNS 还没有完全切过去。**

这也是自己折腾网站比较有意思的地方。

很多问题最后看起来都很小。

但在找到答案之前，总得绕一圈。

---

真正让我觉得舒服的，是后面的自动部署。

现在我只需要修改 GitHub 里的代码。

然后提交。

Cloudflare Pages 会自动检测到 GitHub 的更新，开始构建。

构建命令就是：

npm run build

输出目录：

dist

构建完成以后，网站自动更新。

整个过程基本不需要我再手动操作服务器。

以前可能会觉得：

“我要发布网站，是不是还得上传文件？”

现在则变成：

“改完，提交。”

然后等一会儿。

网站自己就更新了。

这种感觉其实挺好。

---

而且这也让我重新理解了“自己拥有一个网站”这件事情。

以前我觉得拥有网站，就是拥有一个域名。

后来发现不是。

真正属于自己的东西，应该是：

域名是自己的。

代码是自己的。

文章是自己的。

图片是自己的。

整个构建过程也是自己能够理解的。

至于最终把网站放在哪里，其实反而没有那么重要。

GitHub Pages 可以。

Cloudflare Pages 也可以。

以后如果哪一天我又觉得另一个平台更适合，也完全可以再搬一次。

因为真正重要的东西并没有跟着平台一起消失。

---

所以这次迁移，我其实没有什么特别激动的感觉。

没有“终于摆脱 GitHub Pages”这种想法。

因为 GitHub Pages 本身并没有什么不好。

它免费、简单，而且很好用。

只是对于现在这个越来越喜欢折腾的网站来说，Cloudflare Pages 可能更符合我目前的需求。

它让我继续保留 GitHub 的代码管理方式，同时又可以把部署这件事情交给 Cloudflare。

少一点手工操作。

多一点自动化。

仅此而已。

---

有时候我觉得，折腾个人网站的意义可能也不在于最后用了什么技术。

你当然可以用很复杂的框架。

也可以使用各种数据库、后台和服务。

但最后真正留下来的，还是那些文章。

是某一天突然想记录下来的一个念头。

是一次旅行。

是一段生活。

或者只是某个晚上，突然觉得有一句话值得写下来。

网站只是一个容器。

技术只是让这个容器变得更舒服。

---

所以，我还是挺喜欢现在这个小站的。

它不一定有多少人访问。

也不一定需要做成一个多么专业的网站。

甚至有时候，我折腾半天，可能只是为了改一个很小的细节。

但没关系。

因为这是自己的东西。

想怎么改，就怎么改。

想写什么，就写什么。

今天用 GitHub Pages。

明天换 Cloudflare。

以后说不定还会换到别的地方。

这些都不重要。

重要的是，我依然可以把自己的东西留下来。

所以这次搬迁，

**不是因为 GitHub Pages 不够好。**

只是到了现在，我觉得 Cloudflare 更适合这种属于自己的、还会继续慢慢折腾下去的小网站。
